## 1. 产品是什么

**Claude Code Anywhere（随行终端）** 是一款远程终端产品。用户可以在手机、平板、笔记本、任意浏览器上，远程操控运行在服务器或本地电脑上的 AI 编程助手（Claude Code）。

**一句话理解**：把你电脑上的终端（黑底白字那个窗口）搬到手机上用。

**不是什么**：

- 不是聊天应用（没有气泡消息）
- 不是代码编辑器（不显示文件树）
- 是一个**真正的终端**，跟 macOS Terminal / iTerm2 一样，只不过是远程的

## 5. 设计约束（红线）

以下是产品决策层面的硬性约束，设计不可违反：

### 5.1 终端渲染规则

| 约束                  | 说明                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| **固定 120 列**       | 终端永远是 120 列宽，不跟随屏幕宽度变化                               |
| **CSS 缩放适配**      | 手机竖屏（约 45 字符宽）通过整体缩小来显示完整 120 列，用户可双指放大 |
| **不支持动态 resize** | 用户不能拖拽改变终端列数，只能调整行数                                |
| **统一渲染引擎**      | 所有平台用同一套终端渲染（xterm.js），确保显示完全一致                |

### 5.2 审批 UI 规则

| 约束                 | 说明                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| **不做模态弹窗**     | 审批操作不用弹窗、不用浮动按钮、不用通知条                                                     |
| **终端内加粗加亮**   | AI 在终端里自己渲染了审批按钮（"允许"/"拒绝"），我们只把这些按钮文字加粗加亮，让用户更容易看到 |
| **不做飞书审批卡片** | 飞书通知只发纯文本 + 跳转链接，不做交互式审批卡片                                              |

### 5.3 通知规则

| 约束           | 说明                                           |
| -------------- | ---------------------------------------------- |
| **设备优先级** | 多设备在线时优先通知电脑端，不是所有设备同时响 |
| **已读消偿**   | 一个设备上处理了通知，其他设备自动取消该通知   |
| **不自动拒绝** | AI 等待审批时永远等下去，不会超时自动拒绝      |

### 5.4 输入规则

| 约束               | 说明                                               |
| ------------------ | -------------------------------------------------- |
| **FIFO 队列**      | 所有设备的输入按先来后到排队，没有 VIP             |
| **Ctrl+C 不排队**  | 中断信号（Ctrl+C）任何时候立即送达，不排队         |
| **离线输入要确认** | 断线期间输入的命令，重连后必须让用户勾选确认才发送 |

## 7. 桌面端 / Web 界面设计

### 7.1 主终端界面（P-02）— 核心页面

```
┌─────────────────────────────────────────────────────────────┐
│ ┌─ 顶栏 ──────────────────────────────────────────────────┐ │
│ │ [设备名称 ▼]  [实例: my-project ▼]     🔔(3)  🟢已连接 │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌─ 侧边栏(可选) ─┐ ┌─ 主终端区域 ────────────────────────┐ │
│ │                  │ │                                      │ │
│ │ 📂 /home/project │ │  $ claude                            │ │
│ │   ├ 实例 #1 🟢   │ │                                      │ │
│ │   └ 实例 #2 🟡   │ │  Claude Code v4.6                    │ │
│ │                  │ │  > 正在分析代码...                     │ │
│ │ 📂 /home/api     │ │                                      │ │
│ │   └ 实例 #3 🟢   │ │  ╔══════════════════════════╗        │ │
│ │                  │ │  ║  是否允许执行 rm -rf?    ║        │ │
│ │ [+ 新建实例]     │ │  ║  [██ 允许 ██] [拒绝]    ║        │ │
│ │                  │ │  ╚══════════════════════════╝        │ │
│ │──────────────── │ │                                      │ │
│ │ ⚙️ 管理面板     │ │                                      │ │
│ └──────────────────┘ └──────────────────────────────────────┘ │
│ ┌─ 底栏 ──────────────────────────────────────────────────┐ │
│ │ 队列(2) ▲  │ 📱iPhone: "npm test" [取消]  │ 💻Mac: "..." │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ┌─ 输入框 ────────────────────────────────────────────────┐ │
│ │ > 输入命令...                                    [发送] │ │
│ └──────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

**各区域说明**：

#### 顶栏

- **左侧**：设备选择器（下拉菜单）、实例选择器（下拉菜单，显示当前实例名+工作目录）
- **右侧**：通知铃铛（未读数 badge）、连接状态指示器（见 C-01）

#### 侧边栏（V2，可折叠）

- 按工作目录（cwd）一级分组展示实例列表
- 分组标题：粗体显示目录路径，可折叠
- 实例项：名称 + 状态圆点（🟢运行中 / 🟡等待输入 / 🔴错误 / ⚫已停止）+ 最后活动时间
- 当前选中实例高亮（蓝色背景）
- 底部：[+ 新建实例] 按钮、[⚙️ 管理面板] 入口（仅管理员可见）
- 宽度：240px

#### 主终端区域

- xterm.js 渲染，120 列固定宽度
- 深色背景（具体色值待定，见 §11.1）
- 字体：Fira Code Mono，14px
- 光标：实心方块，500ms 闪烁
- 支持鼠标滚轮滚动、文本选择复制（右键菜单）
- **审批按钮**：AI 在终端中渲染的"允许"/"拒绝"按钮，客户端通过 ANSI 样式让它们更醒目（高亮+粗体+下划线），不额外渲染任何 UI 组件

#### 底栏（输入队列面板，V2）

- 默认收起，显示 "队列(N)" 标签
- 点击展开：列出所有排队中的命令
  - 每条：命令文本 + 来源设备名称 + 来源设备图标 + 状态标签
  - 状态：「待执行」灰色 / 「执行中」蓝色闪烁 / 「已发送」绿色勾
  - 可取消自己发送的命令
- 队列为空时显示 "当前无待执行命令"
- 最多显示最近 20 条

#### 输入框

- 底部固定输入框，回车发送
- 离线时：输入框可用，但标注 "已离线，消息将在重连后发送"
- 发送后：显示发送状态（已发送 ✓ / 发送失败 ✕ / 排队中 ⏳）

### 7.2 Agent Team 分窗格模式（V3）

当 AI 启动多个并行子任务（Teammate）时，主终端区域自动分屏：

```
┌─ 主终端区域 ────────────────────────────────────────────┐
│ ┌─ Lead (30%) ─────┐ ┌─ Teammates (70%) ───────────────┐ │
│ │                   │ │ ┌─ Teammate #1 🟢 ──┐           │ │
│ │  主 AI 任务输出    │ │ │ 代码搜索任务       │           │ │
│ │  (可输入)         │ │ │                    │           │ │
│ │                   │ │ └────────────────────┘           │ │
│ │                   │ │ ┌─ Teammate #2 🟡 ──┐           │ │
│ │                   │ │ │ 测试执行任务       │           │ │
│ │                   │ │ │ (等待输入)         │           │ │
│ │                   │ │ └────────────────────┘           │ │
│ └───────────────────┘ └─────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

- **默认比例**：Lead 占 30% 宽度，Teammates 占 70%
- **用户可动态调整**：拖拽分割线可自由调整 Lead 与 Teammates 的宽度比例
- 每个 Teammate 独立 xterm.js 渲染
- Teammate 标题栏显示名称 + 状态颜色
- Teammate 退出时窗格自动移除，重新布局
- 切换动画 ≤2s 完成

## 8. 手机端竖屏界面设计

### 8.1 主终端界面

```
┌──────────────────────────┐
│ 顶栏                      │
│ [设备▼] > [实例▼] > 🟢    │
├──────────────────────────┤
│                          │
│                          │
│    xterm.js 终端区域      │
│    (120列 CSS 缩放适配)   │
│    (可双指缩放查看细节)    │
│                          │
│                          │
│                          │
├──────────────────────────┤
│ Agent Tab 栏 (V3)         │
│ [Lead🟢] [#1🟡] [#2🟢]   │
├──────────────────────────┤
│ 修饰键栏 (V3)             │
│ [Ctrl][Alt][Shift][Esc]   │
│ [Tab][↑][↓][←][→]        │
├──────────────────────────┤
│ > 输入命令...      [发送] │
└──────────────────────────┘
```

**竖屏特殊规则**：

- 终端 120 列通过 CSS `transform: scale()` 缩放到屏幕宽度，字小但格式完整
- 用户可双指捏合/展开缩放字号（8px ~ 24px）
- 侧边栏变为顶部下拉菜单
- 实例列表为顶部下拉选择器

### 8.2 Agent Tab 栏（V3）

- 位于终端区域下方
- 每个 Tab 显示 Teammate 名称 + 状态颜色圆点
  - 🟢 运行中（绿色）
  - 🟡 等待输入（黄色）
  - 🔵 处理中（蓝色）
  - ⚫ 已退出（灰色，2s 后消失）
- 点击 Tab 切换到该 Teammate 的全屏终端视图
- Tab 数量超出屏幕宽度时可横向滚动

### 8.3 软键盘修饰键栏（V3，原生 App）

固定在系统键盘上方的工具栏，9 个按键：

```
[Ctrl] [Alt] [Shift] [Esc] [Tab] [↑] [↓] [←] [→]
```

**交互规则**：

- **单击修饰键**：进入"已按下"高亮状态，再按目标键（如字母 C）发送组合键（Ctrl+C），修饰键自动取消高亮
- **双击修饰键**：进入"锁定"状态（类似 Caps Lock），后续所有按键都带该修饰键，再次单击解除
- **多键叠加**：可以同时按下 Ctrl + Shift，然后按目标键发送 Ctrl+Shift+T
- 方向键为普通按键，单击即发送

**视觉状态**：

- 默认：深灰背景，白色文字
- 已按下：蓝色背景，白色文字
- 已锁定：蓝色背景 + 锁定图标

## 10. 核心交互流程

### F-01：首次配对流程（V1）

```
用户打开 Web 页面
    │
    ▼
┌────────────────┐
│ 输入服务器地址   │  默认填充 localhost:8080
│ [地址输入框]     │  支持自定义 IP:Port
│ [下一步]        │
└───────┬────────┘
        │
        ▼
┌────────────────┐
│ 输入配对码       │  6 位数字（有效期 10 分钟）
│ [_ _ _ _ _ _]   │  大号数字输入框
│ [配对]          │
└───────┬────────┘
        │
    ┌───┴───┐
    │       │
    ▼       ▼
  成功     失败
    │       │
    ▼       ▼
┌────────┐ ┌─────────────────────┐
│ 已配对   │ │ 错误提示：              │
│ 为管理员 │ │ "配对码已过期"          │
│ → 终端  │ │ "配对码错误"            │
└────────┘ │ "配对码已被其他设备使用" │
           │ [重新输入]              │
           └─────────────────────┘
```

**关键细节**：

- 首个配对的客户端自动成为管理员，页面显示 "已配对为管理员" 提示
- 后续设备配对显示 "已配对为普通设备"
- 配对成功后自动跳转到主终端界面，设备令牌保存到浏览器 localStorage
- 下次打开自动使用令牌连接，无需再输配对码

### F-02：断线重连 + 离线队列确认（V1）

```
正常使用中
    │
    ▼ 网络中断
┌──────────────────────────────────┐
│ 终端顶部横幅：                     │
│ ⚠️ "连接中断，正在重连（第 1 次）" │
│ 输入框仍可用（输入存入离线队列）    │
│ [取消重连]                        │
└───────────────┬──────────────────┘
                │ 退避重连：1s → 2s → 4s → 8s → 16s → 30s
                │
                ▼ 重连成功
┌──────────────────────────────────┐
│ 横幅变为："已重新连接" (2s 后消失) │
│                                  │
│ ─── 历史输出重放 ───              │
│ (自动补全断线期间的终端输出)        │
│ ─── 重放结束 ───                  │
│                                  │
│ 若缓冲区溢出：                    │
│ ⚠️ "部分历史输出已丢失，           │
│     从 14:32 开始重放"            │
└───────────────┬──────────────────┘
                │
                ▼ 若有离线队列
┌──────────────────────────────────┐
│ 弹出确认对话框：                   │
│                                  │
│ "断线期间您输入了 3 条命令："       │
│ [✓] npm install          14:30  │
│ [✓] npm test             14:31  │
│ [✓] git status           14:33  │
│                                  │
│ [全选] [取消全选]                 │
│              [确认发送] [放弃全部] │
└──────────────────────────────────┘
```

**关键细节**：

- 重连期间输入框仍可用，输入自动存入离线队列
- 离线队列不自动发送、不自动丢弃，等用户主动操作
- 用户可以取消勾选不再需要的命令
- 默认全选

```
                      仅限权限审批事件
                      AI 侧继续等待，永不自动拒绝
```

**已读消偿**：用户在任一设备上操作后，其他设备上的该通知在 2s 内自动标记已读并取消提醒。

## 13. 响应性能要求（设计师需知）

这些指标会影响动画和交互的设计决策：

| 操作                | 响应时间要求 | 设计影响                           |
| ------------------- | ------------ | ---------------------------------- |
| 终端输出显示        | ≤200ms       | 不需要 loading 状态                |
| 实例切换            | ≤500ms       | 可加极简过渡动画，不要用重型动画   |
| 连接状态更新        | ≤3s          | 需要状态指示器实时变色             |
| 队列同步            | ≤1s          | 队列项增删需要动画但要快           |
| 横竖屏切换          | ≤500ms       | 布局过渡要快，不能有明显延迟       |
| Agent Team 布局调整 | ≤2s          | 窗格动画可以稍慢，但要流畅         |
| 首次连接            | ≤10s         | 需要连接进度指示（不能让用户干等） |
| 配对流程            | ≤30s         | 步骤清晰，减少用户输入量           |

## 14. 设计不要做的事（Don'ts）

| ❌ 不要                          | ✅ 应该                          |
| -------------------------------- | -------------------------------- |
| 不要给审批做模态弹窗             | 在终端内把 AI 渲染的按钮加粗加亮 |
| 不要做飞书审批卡片               | 飞书只发文本 + 跳转链接          |
| 不要让终端宽度跟着屏幕变         | 固定 120 列，CSS 缩放适配        |
| 不要做聊天气泡 UI                | 这是终端，黑底白字               |
| 不要给输入做优先级机制           | 所有设备平等排队                 |
| 不要自动发送离线队列             | 必须让用户勾选确认               |
| 不要在 AI 等待审批时自动超时拒绝 | 永远等用户操作                   |
| 不要用浅色主题做默认             | 默认深色（终端用户习惯）         |
| 不要在通知中包含敏感信息全文     | 推送只显示摘要 + 跳转链接        |

## 附录 A：术语表

| 术语                        | 解释                                                          |
| --------------------------- | ------------------------------------------------------------- |
| **Claude Code**             | Anthropic 的 AI 编程助手，运行在终端中                        |
| **PTY**                     | 伪终端（Pseudo Terminal），模拟真实终端的技术                 |
| **xterm.js**                | 浏览器中运行的终端渲染引擎                                    |
| **配对码**                  | 6 位数字一次性凭证，用于设备首次连接认证                      |
| **设备令牌 (device_token)** | 配对成功后签发的长期凭证，后续自动认证                        |
| **管理员**                  | 首个配对的设备自动成为管理员，可管理其他设备                  |
| **实例 (Instance)**         | 一个正在运行的 Claude Code 进程                               |
| **Agent Team**              | Claude Code 的多 AI 协作模式，Lead 指挥多个 Teammate 并行工作 |
| **Teammate**                | Agent Team 中的子 AI 任务，每个有独立终端输出                 |
| **FIFO**                    | 先进先出队列，所有输入按到达顺序排队                          |
| **ACK**                     | 确认消息，表示服务器已收到输入                                |
| **已读消偿**                | 一个设备处理了通知后，其他设备自动取消该通知                  |
| **弹窗加急**                | 最高优先级通知方式，仅用于权限审批等关键事件                  |
| **offset 重放**             | 断线重连时，从断点位置重新播放缺失的终端输出                  |
| **环形缓冲区**              | 固定大小（1MB）的循环存储区，存放最近的终端输出               |
