# 第2章 执行摘要

## 2.1 问题陈述

Claude Code 是一款强大的 AI 编程助手,但目前只能在本地终端中使用。开发者面临以下五大核心痛点:

1. **设备绑定困境**：Claude Code 只能在运行它的设备上使用,无法跨设备操控。开发者在台式机启动的会话无法在笔记本或手机上继续访问,每次切换设备都意味着上下文丢失和任务重启。

2. **移动场景缺失**：手机和平板无法访问正在运行的 Claude Code 会话。当开发者离开工位（通勤、会议、午休）时,完全失去对 AI 执行状态的感知和控制能力。

3. **上下文丢失风险**：离开工位后无法继续监控或干预 AI 执行。Claude Code 可能在等待用户审批,导致任务在用户离线期间停滞数小时,严重影响开发效率。

4. **协作能力受限**：无法在多台设备上同时查看同一个 Claude Code 实例。团队负责人无法在移动端快速切换查看多个并行任务,多个终端窗口的切换繁琐且效率低下。

5. **AI 自主执行的安全隐患**：Claude Code 在无人值守时可能需要权限审批（如文件操作、Git 提交）,无法及时响应导致任务阻塞。Agent Team 等高级功能使长时间无人值守场景越来越常见,远程监控和干预的需求迫在眉睫。

## 2.2 解决方案概述

**Claude Code Anywhere（随行终端）** 是一款专业的远程终端产品,让用户通过 Web、桌面、手机等任意设备远程操控运行在服务器或本地的 Claude Code 实例。

**核心定位**：不是聊天机器人,不是消息桥接,而是**完整的远程终端解决方案**。

**技术架构**：
- 基于 PTY（伪终端）+ xterm.js 实时渲染,完整支持 ANSI 转义序列和 TUI（文本用户界面）
- WebSocket 实时通信,确保输出延迟 ≤200ms
- 1MB 环形缓冲区 + offset 重放机制,支持断线恢复和弱网环境
- 配对码认证体系,管理员权限模型,保障安全接入

> 📐 **参考图表**：[模块图 — 系统架构](diagrams.md#8-模块图--系统架构)（Backend 8 模块 + Frontend 8 模块 + 外部依赖的完整架构视图）

**分阶段交付**：
- **V1 (MVP)**：单设备单实例可靠远程终端,解决远程接入、配对认证、终端渲染、断线恢复、弱网适应
- **V2**：多实例 + 多客户端 + 通知体系,支持多端同屏、输入仲裁、通知路由、授权审批
- **V3**：多设备管理 + 原生客户端,提供 Hub+Agent 架构、iOS/Android 原生应用、移动端手势优化、Agent Team 可视化

## 2.3 商业价值

**用户价值**：
- **效率提升**：开发者无需被物理设备绑定,随时随地访问 Claude Code 会话,上下文不丢失
- **移动赋能**：手机成为有效的监控和干预工具,通勤、会议等碎片时间可快速响应 AI 审批请求
- **设备解绑**：任意设备都能接入同一会话,笔记本、台式机、云服务器、手机无缝切换
- **协作增强**：多设备同屏查看,团队负责人可高效管理多个 Agent Team 并行任务

**业务价值**：
- **扩大使用场景**：从「办公桌前」扩展至「任意场景」,提升 Claude Code 的可用时间和使用频次
- **提升用户留存**：解决设备绑定痛点,降低用户切换到其他工具的摩擦成本
- **建立远程终端品类**：在 AI 编程助手赛道中率先提供专业远程终端能力,形成差异化竞争优势

# 第3章 项目概述

## 3.1 背景

Claude Code 是 Anthropic 推出的官方 AI 编程助手 CLI 工具,通过自然语言对话帮助开发者完成代码编写、调试、重构等任务。其核心特点包括：
- **基于终端的 TUI 界面**：丰富的 ANSI 颜色、实时状态更新、交互式命令输入
- **Agent Team 多智能体协作**：支持多个 Teammate 并行执行任务,自主决策和协同工作
- **长会话上下文保持**：单个会话可持续数小时,积累丰富的项目上下文

然而,Claude Code 目前的设计完全基于本地终端使用,存在以下核心限制：
1. **设备绑定**：只能在启动它的设备上操作,无法远程接入
2. **单一访问点**：同一时刻只能有一个终端窗口访问实例
3. **无移动支持**：手机和平板无法访问或监控
4. **无跨设备同步**：切换设备意味着上下文丢失

随着 Claude Code 使用场景的扩展（特别是 Agent Team 的无人值守执行）,远程监控和操控的需求日益强烈。

## 3.2 当前状态

**技术现状**：
- Claude Code 运行在本地终端中,基于 Node.js + TypeScript 构建
- 使用标准输入输出（stdin/stdout）进行交互
- 不提供任何网络服务或远程接口
- 所有状态和上下文仅存在于本地进程内存中

**用户行为现状**：
- 用户必须物理接触或 SSH 登录到运行 Claude Code 的设备
- 离开工位后完全失去对 AI 执行状态的感知
- 多设备用户需要在每台设备上独立启动会话,无法共享上下文
- 需要审批时,用户必须返回设备才能响应

**痛点量化**（基于目标用户访谈和社区反馈推估，待 Beta 数据验证）：
- 多数用户在调研中表示「需要跨设备访问能力」
- Agent Team 用户频繁遇到「离开工位后任务因等待审批而停滞」
- 设备切换导致的上下文丢失是高频痛点

## 3.3 目标状态

**产品愿景**：让 Claude Code 成为真正的「随行助手」,用户无论在何时何地、使用何种设备,都能无缝接入和操控。

**核心能力目标**：
1. **远程接入**：任意设备通过 Web/桌面/手机客户端连接到运行中的 Claude Code 实例
2. **完整终端体验**：远程客户端提供与本地终端一致的 TUI 渲染、ANSI 支持、交互能力
3. **多端同屏**：多个设备同时查看同一实例,输出实时同步,输入有序管理
4. **断线恢复**：网络中断后自动重连,历史输出完整恢复,无需重启会话
5. **移动友好**：手机端提供优化的软键盘、手势操作、通知推送、深度链接
6. **多实例管理**：单个客户端可管理多个 Claude Code 实例,快速切换
7. **安全可控**：配对码认证、管理员权限、设备管理、吊销机制

**用户体验目标**：
- 开发者在台式机启动 Claude Code 后,通勤途中用手机查看进度并审批权限请求
- 团队负责人在手机上快速切换查看 5 个并行 Agent Team 的执行状态
- 云服务器用户通过 Web 界面操控运行在服务器上的 Claude Code,无需 SSH + Tmux 组合
- 网络波动时,客户端自动重连并恢复到断线前的状态,用户无感知

# 第4章 目标与目的

## 4.1 业务目标

### 4.1.1 扩大使用场景覆盖

**目标描述**：将 Claude Code 的使用场景从「固定办公桌前」扩展至「任意时间、任意地点、任意设备」。

**量化指标**：
- V1 结束时,80% 的目标用户能在至少 2 台设备上接入同一 Claude Code 实例
- V2 结束时,50% 的活跃用户使用过移动端查看或审批功能
- V3 结束时,平均每用户每天跨设备切换次数 ≥2 次

**成功意义**：扩大 Claude Code 的有效使用时间窗口,从日均 2-4 小时提升至 6-8 小时（包含碎片时间）。

### 4.1.2 提升用户留存率

**目标描述**：通过解决设备绑定痛点,降低用户因「设备限制」而流失到其他工具的比例。

**量化指标**：
- 6 个月留存率从当前 65% 提升至 75%
- 「因设备限制而放弃使用」的用户流失原因占比从 18% 降至 5%
- 用户净推荐值（NPS）从 42 提升至 55

**成功意义**：建立用户对 Claude Code 的长期依赖,减少因工具切换导致的学习成本和上下文迁移成本。

### 4.1.3 建立远程终端产品品类

**目标描述**：在 AI 编程助手赛道中率先建立「专业远程终端」能力,形成差异化竞争优势。

**量化指标**：
- 3 个月内至少 2 篇科技媒体报道提及「Claude Code Anywhere 的远程终端能力」
- 6 个月内至少 1 个竞品跟进类似功能（证明品类价值）
- 远程终端功能成为用户选择 Claude Code 的 Top 3 理由之一

**成功意义**：占据用户心智中的「AI + 远程终端」品类定位,提升品牌溢价能力。

## 4.2 用户目标

### 4.2.1 跨设备无缝操控

**用户诉求**：「我希望在台式机启动的 Claude Code 会话,能在笔记本、手机、平板上继续访问,上下文不丢失。」

**交付能力**：
- V1：Web 客户端 + 桌面客户端支持跨设备接入
- V2：多设备同屏查看,输出实时同步
- V3：iOS/Android 原生应用,移动端输入体验优化

**用户收益**：
- 通勤途中用手机查看 Claude Code 执行进度,及时发现问题
- 在家用笔记本继续办公室台式机上的会话,无需重新开始
- 平板横屏查看代码变更,大屏体验接近 PC

### 4.2.2 移动端实时监控与干预

**用户诉求**：「我离开工位后,希望手机能收到 Claude Code 的审批通知,快速响应,避免任务停滞。」

**交付能力**：
- V2：通知路由 + 外部推送（飞书、APNs、FCM）
- V2：终端内审批按钮加粗加亮 + 飞书文本通知（深链跳转客户端）+ 弹窗加急

**用户收益**：
- 会议中收到审批通知,2 分钟完成审批,任务不中断
- 午休时收到飞书通知,点击深链跳转客户端拒绝高风险操作,保护代码安全
- 通勤途中点击推送,直达问题终端,快速定位 Agent Team 异常

### 4.2.3 多实例高效管理

**用户诉求**：「我同时运行多个 Claude Code 实例（前端项目、后端项目、数据脚本）,希望在一个界面中快速切换查看。」

**交付能力**：
- V2：实例列表 + 快速切换（≤500ms）
- V2：支持单设备动态资源检测，按可用内存/CPU 自动计算实例上限（推荐配置下 ≥10）
- V3：Hub+Agent 架构,跨多台服务器管理实例

**用户收益**：
- 团队负责人在手机上查看 5 个 Agent Team 的并行任务状态
- 全栈开发者在一个 Web 页面中切换前端、后端、数据库迁移三个实例
- 云服务器用户管理分布在 3 台服务器上的 8 个 Claude Code 实例

## 6.1 远程接入与认证（V1 MVP）

### FR-001：配对认证与管理员权限

| 属性 | 值 |
|------|-----|
| **ID** | FR-001 |
| **MoSCoW 标签** | MUST |
| **关联史诗** | EPIC-001: 可靠远程终端 |
| **优先级** | P1 |
| **版本归属** | V1 MVP |

**描述**
Server 首次启动时生成 6 位数字配对码（有效期 10 分钟），客户端通过配对码完成认证获取长期 token。第一个完成配对的客户端自动成为管理员，拥有生成新配对码、吊销设备 token、转移管理权等权限。管理权转移为单向即时操作，管理员可指定目标已配对设备立即生效。管理员丢失时可通过 CLI 命令 `claude-anywhere admin reset` 恢复。

**验收标准**
1. Server 启动后在终端打印 6 位数字配对码，有效期 10 分钟
2. 客户端输入正确配对码后获得 32 字节 hex token（客户端明文存储于 Keychain/Keystore），服务端仅存 bcrypt 哈希（成本因子 12）
3. 首个完成配对的设备自动标记为管理员（数据库 is_admin=true）
4. 管理员可在客户端 UI 生成新配对码、吊销指定设备 token、选择已配对设备转移管理权
5. 管理权转移后目标设备立即拥有管理员权限，原管理员降级为普通设备

> 📐 **参考图表**：[时序图 — 配对认证](diagrams.md#2-时序图--配对认证)（含首次配对、已配对重连、管理权转移三条流程）

### FR-003：会话断线恢复

| 属性 | 值 |
|------|-----|
| **ID** | FR-003 |
| **MoSCoW 标签** | MUST |
| **关联史诗** | EPIC-001: 可靠远程终端 |
| **优先级** | P1 |
| **版本归属** | V1 MVP |

**描述**
Server 为每个实例维护 1MB 环形缓冲区，记录全局 offset。客户端断线重连后携带本地最后的 offset，Server 计算差量重放缺失数据。若缓冲区已溢出，发送 gap 通知提示用户有历史输出丢失，并从最早可用数据继续重放。

**验收标准**
1. Server 为每个实例分配 1MB 环形缓冲区，每条输出记录全局递增 offset
2. 客户端重连时通过 WebSocket 消息携带 `last_offset` 参数
3. Server 计算差量（当前 offset - last_offset），若数据仍在缓冲区则全量重放
4. 若缓冲区已溢出，发送 `type: gap` 消息，包含缺失的 offset 范围，客户端 UI 显示黄色提示条
5. 重连后客户端自动滚动到最新输出位置

**验收标准**
1. 外部推送消息的 `url` 字段包含深链 scheme（如 `claude-anywhere://instance?id=xxx&notification_id=yyy`）
2. 移动端 App 注册深链 scheme，点击推送后唤起 App 并解析参数
3. 客户端根据 instance_id 切换到对应实例，根据 notification_id 滚动到相关输出位置或弹出审批对话框
4. 若 App 未启动则先启动并自动完成跳转
5. 实测从推送点击到终端视图显示耗时 ≤3s

### US-01: 远程接入与会话连续性

**作为**全栈独立开发者小明,**我希望**能够通过任何设备安全快速地接入正在运行的 Claude Code 实例并立即看到最新的终端状态,**以便**在离开工位后仍能监控和操控 AI 任务的进展。

#### 使用场景

1. **首次配对**: 在云服务器上启动 Claude Code Anywhere Server,终端打印 6 位配对码,在手机 Web 端输入配对码完成首次认证,自动成为管理员
2. **快速重连**: 第二次打开 Web 端时,使用已保存的设备令牌自动登录,无需再次输入配对码
3. **会话恢复**: 断线后重新连接,自动从 offset 位置重放最近 1MB 的输出历史,看到完整的上下文
4. **实时终端渲染**: 远程查看 Claude Code 的 TUI 界面(如进度条、表格、彩色日志),显示效果与本地终端一致
5. **低延迟交互**: 在 Web 端输入命令后,200 毫秒内看到终端响应,体验接近本地
6. **配对码过期处理**: 11 分钟后尝试使用过期的配对码,收到明确错误提示并引导在服务端生成新配对码
7. **管理权转移**: 管理员在 Web 端将管理权限转移给另一台已配对的设备,操作在 2 秒内生效
8. **设备令牌吊销**: 管理员吊销某个已配对设备的令牌,该设备立即被拒绝连接并收到引导重新配对的提示
9. **管理员丢失恢复**: 管理员设备丢失后,在服务端运行 `claude-anywhere admin reset` 命令,使用新配对码重新建立管理员

- **Then**: 返回设备令牌,客户端保存到本地存储,首个配对设备自动获得管理员角色

**AC-02: 会话恢复完整**

- **Then**: Server 从 offset X 重放所有历史输出至当前位置,客户端终端显示无缝衔接

**AC-03: 管理员操作生效**
- **Given**: 设备 A 是当前管理员
- **When**: 设备 A 发起管理权转移至设备 B 或吊销设备 C
- **Then**: 操作在 2 秒内生效,设备 B 获得管理权限,设备 C 下次连接被拒绝并收到引导提示

### US-02: 弱网与断线恢复

**作为**在地铁/电梯中通勤的开发者小明,**我希望**在网络不稳定时终端连接能自动恢复且不丢失输入和输出,**以便**无需手动重启或重新输入命令就能继续任务。

#### 使用场景

1. **断线检测**: WebSocket 连接断开后,客户端在 3 秒内显示「连接中断」状态,不再接受新输入
2. **自动重连**: 断线后客户端使用指数退避策略(1s → 2s → 4s → 8s → 16s → 最大 30s)自动重连,无需用户操作
3. **输出不丢失**: 断线期间 Server 持续缓冲输出,重连后自动推送缺失的数据至客户端
4. **输入 ACK 确认**: 客户端发送命令后,3 秒内收到 Server 的 ACK 确认,界面显示「已发送」状态
5. **输入自动重试**: 网络抖动导致命令未收到 ACK,客户端在 5 秒后自动重试发送,Server 端去重避免重复执行
6. **离线队列暂存**: 断线时用户输入的命令暂存到本地离线队列,显示「待发送」标记
7. **重连后二次确认**: 重连成功后,客户端弹出离线队列列表(如「ls -la」、「git status」),用户勾选需要执行的命令后批量发送
8. **弱网批量推送**: Server 检测到客户端网络延迟升高,自动将输出分组批量推送,减少 WebSocket 帧数
9. **缓冲区溢出处理**: 断线超过 5 分钟导致 1MB 缓冲区溢出,重连后显示 gap 提示「部分历史输出已丢失」,从最早可用数据重放
10. **心跳保活**: 15 秒心跳间隔,45 秒无响应判定超时,客户端主动断开并进入重连流程

#### 验收标准

**AC-01: 断线自动恢复**
- **Given**: WebSocket 连接中断
- **When**: 客户端使用退避策略重连成功
- **Then**: 5 秒内恢复连接,自动重放缺失的输出,连接状态变为「已连接」

**AC-02: 输入去重与重试**
- **Given**: 客户端发送命令「ls -la」后未收到 ACK
- **When**: 5 秒后自动重试
- **Then**: Server 通过消息 ID 去重,命令仅执行一次,客户端收到 ACK 显示「已发送」

**AC-03: 离线队列二次确认**
- **Given**: 断线期间用户输入 3 条命令
- **When**: 重连成功后弹出离线队列确认对话框
- **Then**: 用户勾选 2 条命令并确认,仅这 2 条命令被发送至 Server 执行

#### 优先级
**P1** (V1 MVP 核心功能)

#### 故事点估算
**13 点** (技术复杂度高:需实现 WebSocket 状态机、心跳机制、退避重连、输入 ACK/去重、离线队列)

### US-03: 通知与授权闭环

**作为**需要离开工位的开发者小明,**我希望**Claude Code 需要权限审批时能第一时间通知到我的手机并允许我快速审批,**以便**AI 任务不会因为无人值守而长时间阻塞。

#### 使用场景

1. **设备优先级通知**: Claude Code 请求删除文件权限,优先通知最近活跃的设备,若 30 秒内无用户交互则通知下一优先级设备
2. **已读消偿**: 用户在任一设备上产生交互行为（窗口获焦+未读通知/终端输入/点击推送/操作审批按钮）,其他设备的相同通知自动消失
3. **客户端内审批**: 在终端中 Claude Code 原生渲染的审批提示按钮已被加粗加亮,用户点击后审批结果立即发送至 Server,Claude Code 继续执行
4. **飞书文本通知**: 所有客户端断线时,Server 触发飞书机器人发送文本消息（含审批摘要 + 客户端深链）,用户点击深链跳转客户端完成审批
5. **CC 持续等待**: Claude Code 侧保持持续等待,不设超时自动拒绝,用户可在任意时间完成审批
6. **外部推送升级链**: 所有客户端离线 2 分钟后触发手机推送(APNs/FCM,含深链) → 再等 3 分钟无响应触发飞书文本通知（含深链） → 权限审批事件在飞书后仍无响应触发弹窗加急
7. **推送点击直达**: 点击手机系统推送,App 自动打开并跳转至对应实例的终端视图
8. **审批历史记录**: 在客户端查看最近 50 条权限审批记录(时间、事件、决策、操作人)

#### 验收标准

**AC-01: 通知优先级与消偿**
- **Given**: 手机和 Web 端同时在线,手机端最近 1 分钟有交互
- **When**: Claude Code 请求危险操作权限
- **Then**: 手机端立即收到通知,Web 端 2 秒后才收到;手机端点击后 Web 端通知在 2 秒内消失

**AC-02: 外部推送兜底**
- **Given**: 所有客户端离线
- **When**: 权限请求发出且 2 分钟内无客户端上线
- **Then**: 触发系统推送(APNs/FCM,含审批摘要+深链)；再等 3 分钟无响应触发飞书文本通知（含深链）；权限审批事件在飞书后仍无响应触发弹窗加急

**AC-03: CC 持续等待**
- **Given**: 权限请求已通过所有外部通知渠道发出（推送 + 飞书）
- **When**: 长时间无任何审批响应
- **Then**: CC 侧保持持续等待状态不自动拒绝；用户随时可通过客户端完成审批

#### 优先级
**P2** (V2 核心功能)

#### 故事点估算
**8 点** (需对接外部推送服务,实现通知路由和已读消偿逻辑)

### US-05: 多端输入协同

**作为**同时使用手机和电脑的开发者阿丽,**我希望**在任一设备输入命令时其他设备能实时看到输入队列状态,**以便**避免重复输入和冲突。

#### 使用场景

1. **输入队列可见**: 手机端输入「npm install」后,Web 端立即显示队列中有 1 条待执行命令
2. **FIFO 公平排队**: 手机端输入命令 A,Web 端输入命令 B,Server 按接收顺序依次执行,两端终端显示一致
3. **队列状态同步**: 命令 A 开始执行,两端队列显示更新为「执行中」;完成后队列清空,同步延迟 ≤1 秒
4. **取消队列命令**: 手机端在队列中点击取消命令 B,Web 端队列 1 秒内同步移除该命令
5. **Ctrl+C 立即发送**: Web 端按下 Ctrl+C,不进入队列,立即发送至 Claude Code 中断当前执行,手机端 1 秒内看到中断结果
6. **设备平等原则**: 无论管理员还是普通已配对设备,输入命令享有平等优先级,不存在抢占机制

#### 验收标准

**AC-01: 队列同步实时**
- **Given**: 设备 A 发送命令进入队列
- **When**: 设备 B 正在查看终端
- **Then**: 设备 B 在 1 秒内看到队列更新,显示命令来源设备名称和排队位置

**AC-02: FIFO 严格执行**
- **Given**: 设备 A 发送命令「echo A」,100 毫秒后设备 B 发送「echo B」
- **When**: Server 依次执行
- **Then**: 终端输出顺序为 A → B,所有设备终端显示一致

**AC-03: Ctrl+C 不排队**
- **Given**: 队列中有 2 条待执行命令
- **When**: 设备 A 发送 Ctrl+C 信号
- **Then**: 信号立即发送至 Claude Code,当前执行中断,队列命令仍保留(除非用户手动取消)

#### 优先级
**P2** (V2 核心功能)

#### 故事点估算
**5 点** (需实现输入队列 FIFO 逻辑和状态广播机制)

# 第9章 用户体验需求

## 用户流程

### 1. 首次配对流程

**流程描述**: 用户第一次将客户端设备连接至 Claude Code Anywhere Server 的完整流程。

> 📐 **参考图表**：[时序图 — 配对认证](diagrams.md#2-时序图--配对认证)（流程 A — 首次配对）

**步骤详解**:
1. **Server 启动**: 用户在设备(如云服务器)上运行 `claude-anywhere start`,Server 启动成功
2. **打印配对码**: Server 在终端输出 6 位数字配对码(如 `123456`),并显示「配对码有效期 10 分钟」提示
3. **客户端输入**: 用户在手机 Web 浏览器打开 `https://anywhere.claude.ai`,进入配对页面,输入 `123456`
4. **完成认证**: Server 验证配对码成功,生成设备令牌并返回给客户端,客户端保存到本地存储(localStorage/Keychain)
5. **进入终端**: 客户端自动跳转至终端视图,显示当前实例的实时输出,用户可立即开始操作

**关键交互**:
- 配对页面提供「Server 地址」输入框(默认 `localhost:8080`,支持自定义 IP)
- 配对成功后显示「已配对为管理员」提示
- 配对失败显示具体错误(如「配对码已过期」「配对码错误」),并引导用户刷新配对码

**涉及需求**: FR-001, SC-006, SC-007

### 2. 断线恢复流程

**流程描述**: 网络中断后客户端自动重连并无缝恢复会话的流程。

> 📐 **参考图表**：[时序图 — 断线重连与输出重放](diagrams.md#4-时序图--断线重连与输出重放) | [状态图 — 客户端连接状态机](diagrams.md#9-状态图--客户端连接状态机)

**步骤详解**:
1. **检测断线**: WebSocket 连接关闭,客户端在 3 秒内检测到断线(通过心跳超时或 `onclose` 事件)
2. **状态显示**: 终端顶部显示「连接中断,正在重连...」横幅,输入框禁用,不再接受新输入
3. 客户端使用退避策略重连:第 1 次等待 1 秒,第 2 次 2 秒,第 3 次 4 秒,第 4 次 8 秒,第 5 次 16 秒,最长 30 秒
4. **offset 重放**: 重连成功后,客户端发送上次记录的 offset 值,Server 从缓冲区重放缺失的输出数据
5. **无缝恢复**: 终端自动显示重放的历史输出 + 最新的实时输出,横幅消失,输入框恢复可用,显示「已重新连接」提示 2 秒后自动隐藏

**关键交互**:
- 重连中显示重试次数(如「第 3 次重连中...」)
- 若缓冲区溢出,显示「部分历史输出已丢失,从 X 时间开始重放」提示
- 用户可手动点击「取消重连」按钮,终止自动重连

**涉及需求**: FR-003, FR-019, SC-003, SC-005

### 3. 权限审批流程

**流程描述**: Claude Code 请求敏感操作权限时,通知用户并等待审批的完整流程。CC 侧保持持续等待,不设超时。

> 📐 **参考图表**：[时序图 — 授权审批闭环](diagrams.md#7-时序图--授权审批闭环)（含完整升级链：设备优先级 → 推送 → 飞书 → 弹窗加急 → CC 持续等待）

**步骤详解**:
1. **事件触发**: Claude Code 尝试删除文件,触发权限请求事件(如 `permission:file_delete`),CC 进入持续等待状态
2. **设备优先级通知**: Server 检测到手机端 1 分钟内有交互(最近活跃设备),优先向手机端推送审批事件
3. **已读消偿**: 手机端用户看到终端中 Claude Code 渲染的审批提示(按钮已被客户端加粗加亮),Server 收到「已读」事件,取消向其他设备的通知推送
4. **审批操作**: 用户直接在终端中点击 Claude Code 原生渲染的审批按钮(客户端仅做视觉加粗加亮,不额外渲染 UI)
5. **结果同步**: Server 将审批结果(允许)同步至 Claude Code PTY,Claude Code 继续执行删除操作,所有客户端终端显示「权限已批准,操作继续」

**关键交互**:
- 所有客户端离线 2 分钟后触发手机推送(APNs/FCM,含审批摘要 + 客户端深链)
- 推送后 3 分钟仍无响应,发送飞书文本消息(仅告知审批内容 + 客户端深链,不含交互式审批按钮)
- 飞书通知后仍无响应,权限审批事件触发弹窗加急(最高优先级通知)
- CC 侧始终保持等待,不自动拒绝;用户可在任意时间打开客户端完成审批
- 审批历史可在「设置 → 审批记录」中查看

**涉及需求**: FR-008, FR-009, SC-015, SC-016, SC-017

## 第17章 附录

### 17.1 术语表

| 术语 | 英文 | 定义 |
|-----|------|------|
| **设备** | Device | 运行 Claude Code 实例的物理或虚拟主机。在 V1/V2 阶段指单台服务器；在 V3 Hub 架构下可指多台 Agent 设备。 |
| **已配对设备** | Paired Device | 通过配对码认证成功的客户端设备。每个已配对设备持有 device_token，无需重复配对。 |
| **配对码** | Pairing Code | 6 位数字一次性凭证，有效期 10 分钟。Server 首次启动时自动生成首次配对码，后续由管理员按需生成。 |
| **管理员** | Administrator | 拥有生成配对码、吊销设备 token、转移管理权等权限的已配对设备。每个 Server 同一时间只有一个管理员，基于首次配对确立。 |
| **实例** | Instance | 一个正在运行的 Claude Code 进程。可以是独立实例、Agent Team Lead 或 Teammate。每个实例有独立的 PTY、输出缓冲区、输入队列。 |
| **输出缓冲区** | Output Buffer | 每实例维护的环形缓冲区，容量 1MB。记录全局写入 offset（单调递增），支持按客户端 lastOffset 重放缺失输出。 |
| **输入队列** | Input Queue | 每实例维护的先进先出（FIFO）队列。所有设备的输入平等入队，Claude 实例空闲时自动 dequeue 下一条输入注入 PTY stdin。 |
| **环形缓冲区** | Ring Buffer | 固定大小的循环队列，写满后覆盖最旧数据。用于存储实例输出，支持断线恢复场景下的输出回放。 |
| **offset 重放** | Offset Replay | 断线重连时，客户端发送 lastOffset，服务端从该 offset 开始重放缓冲区中的缺失输出，实现会话恢复。 |
| **gap 通知** | Gap Notification | 当客户端请求的 offset 已被环形缓冲区覆盖时，服务端发送的数据缺口提示，告知用户部分历史输出已丢失。 |
| **离线队列** | Offline Queue | 客户端完全断网时，将未发送的输入缓存到本地的队列。重连后展示给用户确认（勾选框，默认全选）后发送。 |
| **输入 ACK** | Input Acknowledgement | 服务端收到输入后回复的确认消息。客户端根据 ACK 判断输入是否送达，3 秒未收到 ACK 则自动重试。 |
| **三态状态机** | Three-State Machine | 客户端连接状态机，包含三种状态：CONNECTED（已连接）、DEGRADED（弱网）、DISCONNECTED（已断开）。 |
| **弱网模式** | Degraded Mode | 心跳检测超时时客户端自动切换到的模式。输出降频为批量推送（每 2 秒合并），减少带宽消耗。 |
| **设备优先级通知** | Priority Notification | 多设备在线时按用户配置的优先级顺序通知（默认优先电脑端）。优先设备响应后通过已读消偿取消其他设备的通知。 |
| **已读消偿** | Read Dismissal | 用户在任一设备上响应通知后，系统广播 `notification_dismiss` 给其他设备，取消重复提醒。 |
| **外部推送** | External Push | 所有客户端离线时，通过 APNs/FCM 推送和飞书文本通知（含客户端深链）等外部渠道通知用户。 |
| **Hub 架构** | Hub Architecture | V3 阶段的架构模式，Hub 统一管理多台 Agent 设备上的所有实例，提供多设备统一接入和管理能力。 |
| **Agent Team** | Agent Team | Claude Code 的高级功能，Lead 代理可创建多个 Teammate 并行执行任务。本产品通过 Hook 事件检测 Teammate 并提供可视化布局。 |
| **Teammate** | Teammate | Agent Team 模式下由 Lead 创建的子代理实例，拥有独立的 PTY 和输入队列。 |
| **Hook 事件** | Hook Event | Claude Code 触发的特定事件（如 SubagentStart/SubagentStop），本产品监听这些事件以检测 Teammate 创建和退出。 |
